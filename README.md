# Shyngan — визуальный профиль университета

Рабочий продукт: **https://shyngan.vercel.app**
Репозиторий: **https://github.com/kiddorri/shyngan**
Кейс: LOCUS Startup Hackathon 2026, кейс 01 «Визуальный профиль университета», код `LOCUSCASE1`.

Сервис принимает название вуза и за считанные секунды собирает визуальный профиль кампуса:
фотографии из открытых источников, разложенные по категориям, с кликабельным источником и
результатом проверки у каждого снимка.

Главный тезис: **не «вот фотографии вуза», а «вот почему этой фотографии можно верить».**
Каждая строка в панели доказательств соответствует проверке, которая реально выполняется в коде.
Если подтвердить снимок нечем — так и написано, а уровень доверия понижен.

---

## 1. Что видит пользователь

1. Вводит название вуза. Если подходит несколько — сервис показывает список и просит уточнить.
2. Во время сборки идёт поток событий: найден якорь координат, сколько снимков дали Places и сайт
   вуза, сколько отсеяно и по какой причине, сколько запросов ушло к модели.
3. Готовый профиль разделён по происхождению снимков:
   - **Официальные** — опубликованы на домене вуза; провенанс доказан доменом;
   - **Глазами людей** — загружены посетителями в Google Places; провенанс доказан географически;
   - **Вокруг кампуса** — окружение в пешей доступности, не объекты вуза.
4. Внутри секций — группировка по категориям: кампус, аудитории, общежитие, библиотека,
   лаборатории, спорт, студенческая жизнь. Фильтры по категориям — в шапке профиля.
5. Клик по снимку открывает панель доказательств: список выполненных проверок, измеренное
   расстояние до кампуса, вердикт модели о содержимом, источник, дата получения, перцептивный хэш.

## 2. Как проверяется принадлежность снимка

Порядок проверок и пороги (значения — из `lib/profile.ts`, менять их следует там же).

### 2.1. Якорь координат

Точка, относительно которой считается всё остальное. Источники по убыванию силы:

| Источник | Как получен | Последствие для доверия |
|---|---|---|
| `wikidata` | координаты вуза из Wikidata | независимый источник, без понижения |
| `places+2gis` | Google Places и 2ГИС указали на одну точку (расхождение ≤ 500 м) | подтверждение вторым провайдером |
| `places` | только Google Places, подтверждения нет | доверие понижается на уровень |
| `none` | координат нет | расстояние не проверяется, всё «не подтверждено» |

Координат нет у заметной части казахстанских вузов, поэтому путь «Places + 2ГИС» — не
запасной, а рабочий.

### 2.2. Расстояние

| Расстояние до якоря | Уровень |
|---|---|
| ≤ 1500 м | подтверждено |
| ≤ 6000 м | вероятно |
| дальше, но название места совпадает с названием вуза | вероятно (другой корпус) |
| дальше | не подтверждено |
| категория «вокруг кампуса» дальше 2000 м | снимок выбрасывается |

Отдельный порог для окружения нужен потому, что «вокруг кампуса» означает пешую доступность:
без него в профиль попадали городские достопримечательности в нескольких километрах от вуза.

### 2.2.1. Город — другое утверждение

Кейс требует показать и сам город, в котором находится университет. Это отдельная категория
(«Город») с собственной проверкой, потому что утверждение здесь другое: не «это объект вуза», а
«это тот город, где вуз находится». Смешивать их нельзя — иначе центральная площадь оказывается
«неподтверждённым кампусом».

| Проверка | Результат |
|---|---|
| город места совпадает с городом кампуса **и** расстояние ≤ 40 км | тот же город |
| выполнено что-то одно | вероятно тот же город |
| ничего не выполнено | город не подтверждён |

Город берётся из структурного адреса Google Places (`addressComponents`), а не из строки
адреса, и сравнивается с городом **кампуса**, а не с названием из Wikidata. Причина
практическая: справочники называют один город по-разному — в Wikidata «Алма-Ата», в картах
«Алматы», — и сверка по названию из справочника разваливалась на ровном месте.

Модель различить «рядом с кампусом» и «город» не может: на снимке улица и там, и там. Разделяет
их география — запрос и измеренное расстояние, а не содержимое кадра.

**Город показывается общими видами.** Крупный план памятника или вывески — это фотография
предмета, который стоит в городе, а не фотография города. Поэтому:

- запросы нацелены на видовые места: смотровая площадка, набережная, центр города — там
  посетители снимают панорамы, а не детали;
- модель отдельно отвечает, широкий это кадр или крупный план; крупные планы в категорию не
  попадают и считаются отдельной строкой статистики;
- при равном уровне доверия вперёд идёт более широкий кадр.

Важная граница, которая указана и в панели доказательств: расстояние меряется до **отметки места
на карте**, а не до точки, где сделан снимок. Places не сообщает координат съёмки.

### 2.3. Содержимое

Gemini (`gemini-3.8-flash`, структурированный вывод по схеме) отвечает на вопрос «что изображено»:
здание вуза, общежитие, аудитория, библиотека, лаборатория, спорт, студенческая жизнь, город или
«другое». Нерелевантное отсеивается, категория берётся по содержимому, а не по тексту запроса.

Модель **не** спрашивается «тот ли это университет» — на такой вопрос она может ответить только
догадкой. Принадлежность вузу доказывает географический слой либо домен сайта.

### 2.4. Технические фильтры

| Проверка | Порог | Зачем |
|---|---|---|
| дубликаты | dHash, расстояние Хэмминга ≤ 10 | одинаковые и пережатые копии |
| размер (сайт вуза) | ≥ 500 × 300 px | иконки, логотипы, элементы вёрстки |
| резкость | дисперсия лапласиана ≥ 20 | расфокусированные и пустые кадры |
| снимков с одного места | 2 (для окружения — 1) | один и тот же объект с разных сторон |
| снимков в категории | 6 (окружение — 3) | шесть фасадов общежития — это не покрытие категории |
| снимков с сайта вуза | 14 | чтобы один сайт не занял профиль целиком |
| снимков из Places | 30 | общий бюджет |

Всё отсеянное посчитано: числа видны в блоке «Как собран этот профиль» и в потоке прогресса.
Снимок не может исчезнуть молча — это отдельное требование к коду.

## 3. Источники данных

| Источник | Что берём | Ограничения |
|---|---|---|
| Wikidata (SPARQL + Action API) | карточка вуза, координаты, официальный сайт (P856), проверка «это вуз» по цепочке подклассов | SPARQL отвечает 429 под нагрузкой — тогда работает Action API, где проверка мягче |
| Google Places API (New) | места вуза и снимки посетителей, адреса, ссылка на Google Maps | индексирует здания: посетители снимают фасады, интерьеров мало |
| Официальный сайт вуза | снимки со страниц сайта | часть сайтов недоступна из-за битой цепочки TLS-сертификатов |
| 2ГИС Catalog API | подтверждение расположения вторым провайдером | фотографии через API недоступны, используется только геометрия |
| OpenStreetMap (Nominatim) | координаты центра города для расстояния «кампус — центр» | один запрос на профиль; лицензия ODbL требует атрибуции, она есть в интерфейсе |
| Google Places, поле `reviews` | отзывы о кампусе с настоящей датой публикации | авторы не проверены: платформа не сообщает, студент это или гость |
| Gemini API | что изображено на снимке | не подтверждает принадлежность вузу |

### Обход сайта вуза

Читается главная страница и до семи внутренних. Ссылки не берутся подряд: сначала ранжируются.

1. Явные галереи, фотоальбомы, панорамные туры — до трёх страниц.
2. Затем по одной странице на категорию: библиотека, спорт, общежитие, лаборатории, столовая,
   аудитории. Без этого обход упирался в фасады: общая галерея вуза почти всегда состоит из видов
   главного корпуса.
3. Остаток бюджета возвращается общим галереям.

Забираются `og:image`, `<img>` (включая ленивые атрибуты и `srcset`), ссылки на полноразмерные
файлы и **фоновые изображения из CSS** — плитки галерей часто не попадают в `<img>` вообще.

Выбор страницы по тексту ссылки — догадка, а не гарантия. Поэтому профиль показывает список
реально прочитанных адресов, а не утверждение «прочитаны разделы с фотографиями».

**robots.txt соблюдается.** Файл читается до первого обращения к сайту: сначала спрашиваем, потом
заходим. Разделы, закрытые для нашего агента, не запрашиваются — они попадают в оговорки профиля
отдельной строкой, потому что «не нашли» и «не смотрели, потому что сайт попросил не смотреть» —
разные ответы. Правила применяются и к самим файлам изображений этого домена. Если robots.txt
закрывает главную страницу, обход не выполняется вовсе.

**Нагрузка ограничена.** Страницы читаются не больше двух одновременно: у вузовских серверов
бывает немного ресурсов. Если сайт задал `Crawl-delay`, запросы идут по одному с указанной паузой,
а число страниц урезается так, чтобы уложиться в бюджет времени — пауза, о которой попросил сайт,
не обсуждается.

## 3.1. Соответствие требованиям кейса

| № | Требование | Где реализовано |
|---|---|---|
| 1 | Поиск по названию с обработкой неоднозначных запросов | `lib/resolve.ts`: три источника; при нескольких совпадениях интерфейс показывает список кандидатов с городом, страной и типом организации |
| 2 | Фотографии кампуса, общежитий, аудиторий, библиотек и города | план запросов в `lib/profile.ts` + целевой обход сайта; город — отдельная категория со своей проверкой |
| 3 | Автоматическое разделение по категориям | `lib/vision.ts`: категория определяется по содержимому кадра, а не по тексту запроса |
| 4 | Удаление одинаковых, похожих и нерелевантных | dHash + расстояние Хэмминга, отсев по резкости и размеру, вердикт модели о релевантности |
| 5 | Проверка принадлежности снимка | географический слой (якорь + расстояние) и провенанс по домену; отдельная проверка для города |
| 6 | Кликабельный источник и дата | ссылка на страницу места или сайта у каждого снимка; дата получения у всех, дата публикации — у отзывов |
| 7 | Краткое описание кампуса | `lib/describe.ts`: собирается только из найденных данных |
| 8 | Фильтры «общежитие», «спорт», «лаборатории», «студенческая жизнь» | фильтры по всем категориям в шапке профиля; пустые помечены и недоступны |

Дополнительные функции из кейса:

| Функция | Состояние |
|---|---|
| Карта кампуса и расстояние до центра города | сделано: план мест с кольцами порогов и лучом на центр города, расстояние измеряется до точки OpenStreetMap |
| Показатель достоверности каждого материала | сделано: три уровня плюс список выполненных проверок у каждого снимка |
| Фотографии и отзывы студентов | частично: снимки посетителей и отзывы о кампусе с датой публикации; авторов платформа не раскрывает, поэтому студенческими они не называются |
| Сравнение двух университетов | не сделано |
| Климат, транспорт, стоимость жизни | не сделано: нет источника, качество которого мы могли бы проверить так же, как остальные |

## 4. Архитектура

```
app/
  page.tsx              интерфейс: поиск, секции, фильтры, панель доказательств
  api/resolve/route.ts  GET /api/resolve?q=<название> → кандидаты
  api/profile/route.ts  GET /api/profile?qid=<id>     → поток NDJSON
lib/
  resolve.ts            название → вуз: Wikidata SPARQL → Action API → Google Places
  wikidata.ts           SPARQL: карточка, координаты, сайт, проверка «это вуз»
  wikidata-api.ts       запасной путь через Action API при отказе SPARQL
  places.ts             клиент Google Places: searchText, Place Details, photo media
  twogis.ts             поиск организации в 2ГИС для подтверждения координат
  official.ts           обход сайта вуза с соблюдением robots.txt, сбор кандидатов
  osm.ts                центр города через Nominatim (OpenStreetMap) для расстояния
  image.ts              загрузка, нормализация, dHash, метрика резкости
  vision.ts             Gemini: что изображено, батчами, со структурной схемой
  profile.ts            оркестратор: якорь, сбор, фильтры, доверие, покрытие
  describe.ts           краткое описание кампуса только из найденных данных
  types.ts              единственный источник правды для типов
pipeline-test.mts       оффлайн-стенд: весь пайплайн с полностью подменённой сетью
```

Профиль отдаётся потоком NDJSON: события прогресса идут по мере выполнения, последняя строка —
готовый профиль. Поэтому пользователь видит, что происходит, а не крутящийся индикатор.

## 5. Запуск

```bash
npm ci
cp .env.example .env.local   # и вписать ключи
npm run dev                  # http://localhost:3000
```

Переменные окружения:

| Переменная | Обязательна | Назначение |
|---|---|---|
| `GOOGLE_PLACES_API_KEY` | да | места и снимки Google Places |
| `GEMINI_API_KEY` | нет | проверка содержимого; без неё доверие ограничено уровнем «вероятно», и профиль об этом сообщает |
| `TWOGIS_API_KEY` | нет | подтверждение координат вторым провайдером |
| `PLACE_REVIEWS` | нет | значение `off` отключает сбор отзывов: поле `reviews` тарифицируется по более дорогому SKU Places |

Сборка и оффлайн-тест:

```bash
npm run build
npx tsx pipeline-test.mts
```

`pipeline-test.mts` запускается вручную и не входит в сборку Next: вся сеть в нём подменена, поэтому
тест не требует ключей и не тратит квоты. Он проверяет dHash и дедупликацию, разбор HTML и ранг
ссылок, форму запросов к Gemini и 2ГИС, пороги расстояния, отсев размытых, лимиты на место и
категорию, сходимость статистики отсева и поток NDJSON.

## 6. Тестовый сценарий для жюри

1. Открыть https://shyngan.vercel.app и ввести любой казахстанский вуз, в том числе не показанный
   в демо-видео.
2. Замерить время от нажатия «Найти» до появления профиля; в шапке профиля выводится измеренное
   время сборки.
3. Открыть панель доказательств у любого снимка: там перечислены выполненные проверки, измеренное
   расстояние и вердикт модели.
4. Проверить фильтры по категориям; категории без данных помечены и недоступны — это честный
   пробел, а не пустой экран.
5. Ввести заведомо неоднозначное название («КазНУ») — сервис попросит уточнить.
6. Ввести вуз, чей сайт недоступен: профиль соберётся из Places, а причина недоступности сайта
   будет показана в оговорках.

## 7. Известные ограничения

Названы намеренно: пробел, о котором сказано прямо, лучше уверенной выдачи непроверенного снимка.

- **Даты публикации нет.** Ни Google Places, ни страницы сайтов не сообщают дату съёмки или
  публикации. Показывается дата получения снимка, а поле даты публикации остаётся пустым.
- **Аудитории и лаборатории часто пусты.** Places индексирует здания, посетители снимают фасады.
  Целевой обход сайта это частично компенсирует, но если у вуза нет ни одной фотографии
  лаборатории, взять её неоткуда.
- **Часть сайтов вузов недоступна** из-за неполной цепочки TLS-сертификатов. Проверка сертификата
  не отключается: это сделало бы источник ненадёжным. Причина показывается в оговорках.
- **Фотографии 2ГИС через API недоступны**, поэтому 2ГИС используется только для подтверждения
  координат.
- **Виртуальные 3D-туры** — плееры панорам; отдельных файлов-снимков оттуда получить нельзя.
- **Видео с YouTube не используется.** Скачивание видео и извлечение кадров нарушает правила
  платформы; обложки через API почти всегда содержат наложенный текст.
- **Расстояние меряется до отметки места**, а не до точки съёмки: координат съёмки Places не даёт.
- **Демо ориентировано на Казахстан.** Механика не привязана к стране, но словари ссылок и
  запросы к Places настроены на русский и казахский.

## 8. Техническая справка

**Стек.** Next.js 16.3.5 (App Router, Turbopack), React 19, TypeScript, sharp для работы с
изображениями. Хостинг — Vercel. Внешних UI-библиотек нет, стили — CSS-модули.

**Модели и API.** Gemini `gemini-3.8-flash` (`generateContent`, `response_schema`, температура 0,
батчи по 4 изображения, до 5 параллельных запросов, одна повторная попытка на батч);
Google Places API (New) — `places:searchText`, Place Details, photo media; Wikidata SPARQL и
Action API; 2ГИС Catalog API.

**Обработка изображений.** Загрузка с таймаутом 8 с и лимитом 8 МБ, нормализация до 1024 px по
ширине в JPEG, dHash 8×8 бит, дисперсия лапласиана на 256×256 для оценки резкости.

**Безопасность.** Все ключи живут только на сервере и берутся из переменных окружения; в
репозитории их нет. Адрес снимка Places запрашивается с `skipHttpRedirect=true`, поэтому ключ API
не утекает в клиент. У всех внешних запросов стоят таймауты, у обхода сайтов — ещё и лимит на
размер страницы. Проверка TLS нигде не отключается.

**Готовые компоненты.** Шаблон `create-next-app` (структура проекта, конфигурация TypeScript и
ESLint) и перечисленные выше библиотеки. Вся логика кейса — резолв вуза, якорь координат, обход
сайта, фильтры, проверка содержимого, уровни доверия, интерфейс — написана в период хакатона;
история Git это показывает.
